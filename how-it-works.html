In plain language

How a broadcast becomes data you can trust

No jargon, no computer-vision vocabulary. If any of this is unclear, that is a bug in the writing — the product is meant to be usable without reading it at all.

The six steps

Steps one to five are the machine. Step six is a person, and it is not optional: nothing appears on a public page until someone has looked at what the detector read and said yes.

What “published” means here

A published line-up has all four of these

  • Five heroes read off the actual broadcast frame, not entered by hand from memory.
  • A confidence score the detector was willing to stand behind, or a person's explicit approval.
  • The image file it was read from, kept and linked.
  • A named review status of reviewed or auto-high. Anything else is withheld.

Where the facts come from

Two separate sources that never mix:

  • Hero compositions only ever come from reading the video, or from a person correcting that reading. FACEIT can never supply a composition.
  • Match facts — teams, maps, scores, bans — come from FACEIT, official pages, or manual entry.

Keeping them apart is why a score being wrong can never make a composition wrong, and vice versa.

What happens when the machine is wrong

It gets corrected, and the original reading is kept.

A correction never deletes what the detector saw. It is recorded as an additional, attributed, reversible layer: the hero it read, the confidence it had, the frame it read from, who overruled it, when, and why. Both sit side by side in the record, and the correction file is committed to git — so the history of every change is public and permanent.

This is deliberate. A tracker that quietly overwrites its own mistakes cannot be audited, and a tracker that cannot be audited is just an opinion.

Running your own copy

The published site is a static file. It has no server, so it cannot download a video — which is why submitting a game here hands you a command instead of pretending to work.

To actually process a broadcast you run the tracker on your own machine. It is free and open, and it does not phone anything home.

  1. Install Python 3.11 or newer, plus ffmpeg and yt-dlp.
  2. Clone the repository and run pip install -r requirements.txt.
  3. Start the local portal: 
    python3 pipeline/serve.py
  4. Open the address it prints. Every page you have seen here works the same way, except now Submit really submits and Review really writes.
